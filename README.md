# 十円ハゲみちゃん / hagemi-android

円形脱毛症の写真を白黒で残し、経過を振り返るAndroidアプリ。Kotlin + CameraX、Android 8.0以降。

## 境界へのピント合わせと固定（0.7.2）

0.7.1で3000×4000pxの保存を実機確認した後も、ピントが合わず細部がぼける問題に対応します。撮影直前のスイッチ操作・待機リセットでAFを解除していた処理を修正し、高解像度の撮影完了通知まで固定を保ちます。PNGへの保存や高解像度設定は維持します。

- 脱毛候補の中央から境界帯へピント位置を移します。640px以下の輝度映像の小さな領域で、髪の模様がある位置と、離れた再試行位置を選びます。選定は最大毎秒2.5回、位置・鮮明さの確認は最大毎秒5回です。青い丸が合わせる場所です。
- AFの測距範囲は小さくし、露出・ホワイトバランスの測光範囲は変更しません。自動解除を無効にし、撮影が終わった後や待機解除時に戻します。撮影中のスイッチOFFや画面停止では、撮影完了前にAFを解除しません。
- 自動・手動のどちらもピント合わせを行います。AF成功後の新しい映像で細部を2回以上確認してから撮影します。AF成功通知が得られなくても、より強い細部の確認が3回以上続く場合は1.4秒以降に撮影できます。古い映像、同じフレームの重複、途中で細部が確認できなくなった場合は撮影条件に使いません。
- 1か所で2.5秒待って合わなければ、別の境界でもう一度試します。失敗のままの時間切れ撮影をやめ、距離や明るさを変える案内を表示します。自動撮影は3秒の待機後に再試行できます。手動では「ピント確認を省略して撮影」も選べます。
- 画面のタップで合わせる位置を指定できます。タップだけでは撮影せず、確認できると丸が緑になって固定します。「ピントを合わせて撮影」で保存します。
- ソナー・自動撮影をONにした場合は、対応する日本語の音声読み上げ機能が端末にあれば静止・距離の案内を読み上げます。音声を初期化できない場合もソナーと画面の案内を使えます。メディア音量を使用します。

鮮明さは平滑化後の局所コントラスト・輪郭・ラプラシアンの試作指標です。低解像度映像の確認であり、保存画像の全域にピントが合ったことや毛根が数えられることを保証しません。端末・髪・照明・撮影距離ごとのしきい値は未検証です。ピント位置の誤選択、手ぶれ、最短撮影距離などの切り分けは実機で継続します。連続解析に対応しない端末では、自動撮影を無効にして手動のAF結果だけを利用します。

自動テストでは撮影完了前にAFを解除しない順序、失敗・古い映像・キャンセル済み通知から撮影しないこと、再試行、タップと明示的な確認省略、鮮明な線とぼかした線・平坦面・ノイズの区別を検証します。以前の鮮明な1枚を640pxへ縮めた画像では細部を確認でき、強くぼかした派生画像では確認できない結果でした。選んだ1枚の検証であり、実機のAFや識別精度の保証ではありません。個人写真・端末機種・検証用座標はソースに含めません。

以下は各バージョン時点の仕様です。

## 低解像度サーチと高解像度撮影（0.7.1）

サーチ用のプレビュー・連続解析は640×480を希望し、検出処理は従来どおり長辺160px以下・毎秒最大5回で行います。静止画は別のJPEGストリームで、CameraXが選べる最大サイズ・画質優先・JPEG品質100を希望します。カメラの再起動で撮影モードを切り替えず、同時に異なる解像度を設定します。端末によって使える組み合わせと実際のサイズは異なり、メーカーのカメラアプリと同じ画素数になる保証はありません。

保存時の長辺3000px制限を外しました。領域復号できるJPEG・PNGなどは元の画素数を保ち、白黒の8bit PNGとして保存します。たとえば4032×3024を2016×1512へ縮める従来の処理を行いません。PNGへの保存で追加のJPEG圧縮劣化を生じさせませんが、撮影時のJPEG圧縮やピンぼけを復元する方式ではありません。PNGはJPEGよりファイルが大きくなる場合があります。

- サーチと静止画は同じ画角を共有し、プレビューは全体を収める表示にします。縦長の画面を埋めるためだけの静止画切り取りを避けます。
- カメラ画面に選択された撮影サイズと解析サイズ、写真の詳細に実ファイルの保存サイズを表示します。高解像度モードで同時起動できなければ通常モードの最大サイズで再試行し、それも失敗した場合は従来どおり手動撮影へ進みます。
- 白黒変換・向き補正は最大約26万画素の帯、PNG圧縮は1行ずつ処理します。写真全体の出力ビットマップを作りません。8種類のEXIF方向を補正し、元の位置情報などをコピーしません。
- HEICなど領域復号できない形式は従来と同様に縮小して読み込みます。上限は長辺2000px・400万画素（低メモリ端末は100万画素）で、2の累乗で間引きます。この場合は写真の詳細に保存サイズと元サイズを両方表示します。
- 毛の候補解析は元画像の小区画を使います。高解像度画像では区画を狭め、余白込みで1000×1000以下に保ちます。解析パラメータの拡大率は2倍までで、それ以上の解像度への検出精度は未検証です。拡大表示は原寸の一部分を読み、一覧や全体図は小さく読み込みます。
- 新規写真はPNG、以前のJPEGも読み込み・判定編集・削除できます。メモと既存の測定値・候補の判定を保持します。以前に縮小保存された写真の細部は戻りません。

### 確認手順と検証の範囲

以前のアプリを削除せず更新し、撮影画面の「撮影」と「サーチ」のサイズを確認します。新しく撮った写真の詳細で保存サイズを確認し、生え際の拡大・解析・判定保存を試します。写真を取り込む場合も同じ手順です。更新前の写真・メモ・判定が残ること、保存中もアプリが応答することを確認します。

自動テストではPNGのCRC・分割・可逆復号、8種類の方向と帯の境界、4032×3024の画素保持と細い線の保持、領域要求の大きさ、旧JPEGと新PNGの記録保存を検証します。領域デコードはRobolectric用アダプタであり、実機の領域デコーダのメモリ使用量やカメラの対応サイズを検証した結果ではありません。端末での撮影時間・保存時間・メモリ・解像度は確認が必要です。ピント改善は `docs/IMPROVEMENTS.md` に継続します。

## 生え際の追跡・拡大確認（0.7.0）

白黒写真から暗い毛の線を細線化し、地肌が見える境界帯の端点を候補として表示します。自動で「毛根」と確定する機能ではありません。毛先・交差・途切れも候補になります。まず1枚の写真で確認用の候補を残せることを検証する段階です。

1. 「写真を取り込む」または撮影で記録し、写真→「サイズ推定」を開きます。
2. 脱毛範囲を黄色い楕円で囲み、「生え際候補を追跡して確認」を押します。比較範囲や本数の入力は不要です。
3. 「全体図」で点を選び、「拡大」で元の保存画像の細部と追跡線を確認します。「印を表示」は消すこともできます。「前へ」「次へ」でも候補を切り替えられます。
4. 各点を「生え際と確認」「保留」「除外」に分け、「判定を保存」を押します。新しい候補はすべて「未確認」です。
5. 写真→「生え際の判定を見る」で再表示します。候補の座標・追跡線・判定・解析時の楕円を端末内に保存します。従来のメモ・範囲・換算値も保持します。

表示する確認数は人が採用した候補の数です。境界の全生え際数や脱毛本数ではなく、今回の候補数は密度・格子換算へ自動反映しません。従来の範囲推定・格子解析は別の検証機能として残ります。短い毛・先細り・重なりなどは確認の手がかりとして表示し、それだけで生え際を除外しません。会話中の検証用番号と、アプリで並べ直した候補番号は対応しません。

### 処理と保存

- 解析はバックグラウンドで512px区画と周辺の余白に分け、全画面の細線化配列を一度に作りません。「中止」や画面を離れる操作でキャンセルします。
- 楕円半径で正規化した距離0.70〜1.45の帯を対象に、3段階の局所二値化・細線化・線の追跡を行います。連結した明るい地肌と毛の両脇の明暗差で絞り、近接候補を統合します。しきい値は試作写真で調整したもので、異なる撮影条件への精度は未検証です。
- 400候補で上限を表示します。上限に達した結果を全数とは扱わず、範囲を狭めて再検証します。再検出・楕円変更後の保存は、以前の判定を置き換えます。
- 新規写真は長辺3000px以下・最大900万画素を目安に白黒JPEGで保存します。低メモリ端末では最大400万画素に抑えます。倍率は2の累乗で間引くため、上限より小さくなる場合があります。対応形式は細い帯ごとに復号し、通常は保存先1枚と帯だけを保持します。対応しない画像形式は長辺1500px以下に落として処理します。
- カメラの希望解像度を上げていますが、実際のサイズは端末とCameraXの選択に依存します。既存の低解像度写真やピンぼけ写真の細部は復元できません。写真取り込みは1枚32MiBまでです。
- 原写真のEXIFの向きを補正し、位置情報などの元メタデータをコピーしません。写真・候補・判定は端末内のみ。検証用の個人写真・座標はリポジトリに含めません。

### 検証の範囲

人工画像による線・交差・点・地肌の判定、座標と判定の保存、旧形式の記録読み込み、メモ・既存の測定値の保持、削除、画面回転・再表示、8種類のEXIFの向きと白黒変換を自動検証します。Robolectricの領域デコーダは画素を返さないため、画素検証にはテスト用アダプタとネイティブのBitmapFactory・Canvasを使います。実機の領域デコーダやメモリ使用量を測ったテストではありません。

同じ検証写真では、移植後の処理と白黒JPEG保存を通して確認済み16点の近くに候補を残せました。選んだ1枚の参照点を保持できたという結果であり、検出率・適合率や別の写真での精度を示しません。実機の処理時間、メモリ、写真選択、拡大操作、判定保存、更新後の既存記録は実際の端末で確認が必要です。撮影のピント改善は引き続き `docs/IMPROVEMENTS.md` で管理します。

## 境界間隔からの三角格子換算（0.6.0）

サイズ推定画面で黄色い楕円を確認し、「境界の間隔と三角格子を解析」を押します。楕円の半径で正規化した距離0.80〜1.45の境界帯から点を抽出し、緑で表示します。従来の比較範囲に依存せず、楕円周辺を再解析します。

2.5解析px未満の近接候補は重複候補として統合します。各点の最近傍距離を画像の縦横比を考慮した解析pxで求め、16区間のヒストグラムを表示します。区間幅は距離の中央値の20%（最低1px）、最後の区間は上限以上です。最頻区間に属する距離の中央値を基準間隔とします。候補12個未満・8方位のうち3区画未満・最頻区間の標本不足・四分位の大きなばらつき・検出上限到達では換算を出しません。これは検証用のヒューリスティックで、統計的な信頼区間ではありません。

楕円の面積A、基準間隔dに対し、均一な正三角形格子の頂点数に対応する `2A / (sqrt(3) * d²)` を参考値として表示します。三角形の枚数ではありません。同一倍率での拡大・縮小は相殺されますが、曲面・角度・検出の偏りは補正しません。境界に沿った一次元の間隔だけで内部の密度は決まりません。この値は内部にも同じ間隔で均一配置される仮定に依存します。

格子表示は候補位置から三角形を構築したものではなく、基準間隔の正三角形格子を楕円内へ重ねる可視化です。1500点相当を超える場合は描画を省略します。検出点の正しさと距離分布を確認後、「格子換算を記録に採用」→保存で記録します。基準間隔は写真面積の平方根で正規化して保存し、範囲・集計点数と一緒に再表示できます。候補点そのものとヒストグラムは再解析します。

### 実機での検証

1. 既存版を削除せず更新し、保存写真→サイズ推定を開く。
2. 黄色い楕円が脱毛範囲に合うよう修正して境界解析を実行する。
3. 緑の点が境界の生え際に対応するか、紫の点にどの誤検出があるか確認する。
4. ヒストグラムの山と基準間隔、格子の細かさを確認する。候補不足などでは理由が出ることを確認する。
5. 採用・保存・再表示で「境界間隔の格子換算」と表示されることを確認する。

実写真での推定精度と再現性は未検証です。人工的なリング配列の検証は実際の毛の配置を証明するものではありません。

## 自動範囲提案・生え際候補カウントの試作（0.5.0）

サイズ推定画面の「脱毛範囲と周囲を自動提案」で、平滑化した低解像度画像から明るい頭皮の範囲を提案し、周囲の小区画から比較範囲を探します。黄色い楕円は自動輪郭そのものではなく、検出領域の外接矩形に基づく近似です。手で囲み直せます。自動提案できない場合は比較範囲を手で指定し、「選んだ比較範囲を自動カウント」で解析します。

保存画像を長辺768px以下に縮小し、比較範囲の局所平均（15×15近傍）から暗い画素を二値化します。8近傍の連結成分を調べ、面積・縦横比・充填率で小さな点や短い線を候補にします。長い毛、画像端につながる成分を除外し、紫の丸を重ねます。二値化表示は比較範囲内だけ切り替えられます。処理は別スレッドで行い、範囲を変更した後の古い結果は反映しません。

これは毛根・毛穴の識別が検証済みのアルゴリズムではありません。髪の交差、影、肌の模様を数えたり、重なった生え際を1つに数えたりします。頭皮が見えない比較範囲・候補ゼロ・500候補の上限到達では仮入力を無効にします。頭皮の可視割合は明るさのヒューリスティックであり、信頼度の保証ではありません。

「点を確認して候補数を仮入力」を押した場合だけ換算値へ使います。候補密度の参考換算と手入力の本数推定を区別して保存・表示し、自動結果を確定した毛の本数と表示しません。候補点と二値化画像は再解析用の一時表示で、保存するのは範囲・入力候補数・候補由来の区別です。

### 自動解析の実機確認

1. 以前のアプリを削除せず更新し、保存写真→サイズ推定を開く。
2. 自動提案を押し、楕円が目的の範囲に合うか確認。合わなければ手で修正する。
3. 周囲の頭皮が見える比較範囲で解析し、紫の点が実際の生え際に対応するか確認する。
4. 二値化表示を切り替え、毛が線としてつながる・影を数える・候補を見落とす状況を確認する。
5. 必要な場合だけ候補数を仮入力し、保存・再表示で「候補密度」の表示が保たれることを確認する。
6. 範囲を動かすと旧解析が解除されること、解析中も画面操作でフリーズしないことを確認する。

実写真での検出精度は未検証です。人工画像のテストを実際の生え際の識別精度と混同しません。

## 範囲・周辺密度からのサイズ推定の土台（0.4.0）

保存写真を開いて「サイズ推定」を選びます。写真をドラッグして脱毛範囲を黄色い楕円で囲みます。周囲の同じ向きの頭皮へ水色の四角い比較範囲を置き、その中で生え際を確認できる毛の本数を手入力すると、次の式で推定します。

`推定本数 = 脱毛範囲（楕円）の画像上の面積 ÷ 比較範囲（四角）の画像上の面積 × 入力本数`

同一写真内で面積比を取るため、同じ平面が同じ倍率で写る条件では撮影距離による倍率が相殺されます。頭の曲面、角度、髪の重なり、比較場所の密度差による誤差は残ります。楕円は輪郭の近似です。実際に抜けた本数や医学的な重症度の値ではありません。毛の生え際を数えられない写真は入力を空欄にし、範囲のみ保存できます。画像内の面積割合は距離に依存するため、それだけで経過比較はしません。cm²の算出・毛の自動検出はまだありません。

範囲・入力本数を既存の日時・メモと同じ端末内に保存し、タイムラインに推定を表示します。元の白黒写真は変更しません。保存時はメタデータをAtomicFileで更新します。写真は既存の長辺1600px以下の保存画像を1枚ずつ使います。

### 実機確認

1. 既存版を削除せず更新し、前の写真・メモが残ることを確認する。
2. 保存写真→サイズ推定→①脱毛範囲を斜めにドラッグして囲む。
3. 本数を空欄で保存し、範囲だけの記録が一覧・再表示・アプリ再起動後にも残ることを確認する。
4. ②比較範囲を黄色い枠と重ならない近くに置き、目視で確認できた毛の本数を入力する。
5. 推定値が表示され、保存後に一覧へ反映されることを確認する。
6. 範囲・本数の再編集と、編集中の画面回転、保存せず戻る動作を確認する。

撮影時のピントと見ずに撮る案内の改善事項は `docs/IMPROVEMENTS.md` に保持しています。

## 頭皮向けの自動撮影条件の調整（0.3.1）

中央の許容範囲を正規化距離0.10から0.18へ広げ、白い楕円で表示します。候補枠の中心が楕円内に入り、約1秒安定するとピント調整へ進みます。隣接フレームの中心移動は0.075、面積変化は60%まで許容し、髪の重なりによる小さな枠の変動で待機し直しにくくしました。画面に安定待ちの進捗とピント調整の状態を表示します。

頭皮では端末のAF成功通知を得られないことがあるため、AFを試みて最大1.4秒待ち、成功通知がなくても候補の位置・サイズ・映像の新しさを再確認して撮影します。ピントの成功を保証する方式ではなく、実機で保存写真の鮮明さを確認する必要があります。候補消失、ガイド外への移動、画面を離れた場合の撮影解除は維持します。

## ソナー音と自動撮影（0.3.0）

撮影画面で「ソナー音・自動撮影」をONにすると、候補が画面中央に近づくほど音が速くなります（メディア音量を使用）。中央付近で約1.6秒、候補の位置・面積が安定すると、その位置でオートフォーカスを行います。ピント成功と最新の候補位置を再確認して1枚撮影・保存し、一覧へ戻ります。手動撮影も使えます。

候補の消失、中央からの移動、位置・面積の急変、フレームの途切れで安定時間をリセットします。スイッチOFF、一覧への移動、アプリのバックグラウンド化で待機と音を解除します。古いフォーカス完了通知からは撮影しません。枠は検出候補なので、別の明るい領域を誤検出するとそこを撮る可能性があります。

### 自動撮影の実機確認

1. 既存版を削除せず更新し、以前の写真とメモが残ることを確認する。
2. メディア音量を上げ、撮影画面でソナー音・自動撮影をONにする。
3. 候補を中央へ寄せ、音が速くなることと、安定・ピント確認後の撮影・保存を確認する。
4. 安定待ち中に候補を外す、隠す、大きく動かすなどして撮影が止まることを確認する。
5. スイッチOFF、一覧へ戻る、ホーム画面へ移動する操作で音と自動撮影が止まることを確認する。
6. ピントが合わない場合に手動撮影できること、1回の自動撮影で写真が重複保存されないことを確認する。

## コントラスト検出の試作（0.2.0）

カメラ映像の明暗差から、暗い髪に囲まれた明るい領域を候補として黄色い枠で表示します。中央の十字と位置の案内を表示します。検出枠は保存写真に焼き込みません。撮影は引き続き手動です。

輝度（Y）成分だけを長辺160px以下へ間引き、毎秒最大5回処理します。明るさの分布に合わせたしきい値、連結領域、周囲の暗い領域の割合、縦横比で候補を絞ります。処理待ちフレームは蓄積せず、解析後は必ずフレームを解放します。プレビューとの座標変換はCameraXの共通Viewportと変換APIを使います。

この段階は検出位置を実写で確かめるための試作です。明るい髪、照明の反射、広い分け目、背景などで未検出・誤検出が起きます。黄色い枠は脱毛症の判定でも範囲の測定値でもありません。音・自動撮影はまだ追加していません。

### 追加の実機確認

1. 既存版を削除せずAPKで更新し、以前の写真とメモが残ることを確認する。
2. 髪と頭皮を同時に映し、黄色い枠が狙う場所に重なるかを縦・横向きで確認する。
3. 明るさや距離を変え、候補が見つかる条件・誤検出する条件を確認する。
4. 候補を中央へ移動したときの案内と、手動撮影・保存を確認する。
5. 数分間のプレビュー、画面回転、一覧への移動と復帰でフリーズしないことを確認する。

## 最初の版（0.1.0）

- 背面カメラの白黒プレビュー・手動撮影
- 写真を白黒JPEGに変換し、日時・任意のメモと端末内に保存
- 新しい順のタイムライン、写真の確認・削除
- カメラ権限を拒否しても一覧を利用可能

写真・メモはアプリ専用領域のみで管理します。ネットワーク権限なし、クラウド送信なし、OSバックアップ無効。アプリの削除・データ消去で記録は失われます。撮影写真をこのリポジトリに追加しないでください。

保存時は長辺1600px以下に縮小し、一覧には小さいサムネイルを読み込みます。画像処理とファイル操作は別スレッドで実施。今後の毛の解析に必要な解像度は、別途実写で検証します。

## 開発・インストール

Android Studioで開き、JDK 17以降・Android SDK 35を用意してGradle同期します。USBデバッグを有効にした実機を接続し、Runで起動します。

```sh
./gradlew assembleDebug testDebugUnitTest lintDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 実機での確認

1. 初回起動・権限の許可／拒否を試す。
2. 背面カメラのプレビューと保存画像が白黒になることを確認する。
3. メモ付きで縦向き・横向きそれぞれ撮影し、写真の向きを確認する。
4. アプリ再起動後に日時・写真・メモが残っていることを確認する。
5. 写真の削除で確認ダイアログが出ること、キャンセルと削除が機能することを確認する。
6. 連続撮影・画面回転・バックグラウンド復帰時の挙動を確認する。
