# 十円ハゲみちゃん / hagemi-android

円形脱毛症の写真を白黒で残し、経過を振り返るAndroidアプリ。Kotlin + CameraX、Android 8.0以降。

## 自動範囲提案・生え際候補カウントの試作（0.5.0）

サイズ推定画面の「脱毛範囲と周囲を自動提案」で、平滑化した低解像度画像から明るい頭皮の範囲を提案し、周囲の小区画から比較範囲を探します。黄色い楕円は自動輪郭そのものではなく、検出領域の外接矩形に基づく近似です。手で囲み直せます。自動提案できない場合は比較範囲を手で指定し、「選んだ比較範囲を自動カウント」で解析します。

保存画像を長辺768px以下に縮小し、比較範囲の局所平均（15×15近傍）から暗い画素を二値化します。8近傍の連結成分を調べ、面積・縦横比・充填率で小さな点や短い線を候補にします。長い毛、画像端につながる成分を除外し、紫の丸を重ねます。二値化表示は比較範囲内だけ切り替えられます。処理は別スレッドで行い、範囲を変更した後の古い結果は反映しません。

これは毛根・毛穴の識別が検証済みのアルゴリズムではありません。髪の交差、影、肌の模様を数えたり、重なった生え際を1つに数えたりします。頭皮が見えない比較範囲・候補ゼロ・500候補の上限到達では仮入力を無効にします。頭皮の可視割合は明るさのヒューリスティックであり、信頼度の保証ではありません。

「点を確認して候補数を仮入力」を押した場合だけ換算値へ使います。候補密度の参考換算と手入力の本数推定を区別して保存・表示し、自動結果を確定した毛の本数と表示しません。候補点と二値化画像は再解析用の一時表示で、保存するのは範囲・入力候補数・候補由来の区別です。

### 自動解析の実機確認

1. 以前のアプリを削除せず更新し、保存写真→サイズ推定を開く。
2. 自動提案を押し、楕円が目的の範囲に合うか確認。合わなければ手で修正する。
3. 周囲の頭皮が見える比較範囲で解析し、紫の点が実際の生え際に対応するか確認する。
4. 二値化表示を切り替え、毛が線としてつながる・影を数える・候補を見落とす状況を確認する。
5. 必要な場合だけ候補数を仮入力し、保存・再表示で「候補密度」の表示が保たれることを確認する。
6. 範囲を動かすと旧解析が解除されること、解析中も画面操作でフリーズしないことを確認する。

実写真での検出精度は未検証です。人工画像のテストを実際の生え際の識別精度と混同しません。

## 範囲・周辺密度からのサイズ推定の土台（0.4.0）

保存写真を開いて「サイズ推定」を選びます。写真をドラッグして脱毛範囲を黄色い楕円で囲みます。周囲の同じ向きの頭皮へ水色の四角い比較範囲を置き、その中で生え際を確認できる毛の本数を手入力すると、次の式で推定します。

`推定本数 = 脱毛範囲（楕円）の画像上の面積 ÷ 比較範囲（四角）の画像上の面積 × 入力本数`

同一写真内で面積比を取るため、同じ平面が同じ倍率で写る条件では撮影距離による倍率が相殺されます。頭の曲面、角度、髪の重なり、比較場所の密度差による誤差は残ります。楕円は輪郭の近似です。実際に抜けた本数や医学的な重症度の値ではありません。毛の生え際を数えられない写真は入力を空欄にし、範囲のみ保存できます。画像内の面積割合は距離に依存するため、それだけで経過比較はしません。cm²の算出・毛の自動検出はまだありません。

範囲・入力本数を既存の日時・メモと同じ端末内に保存し、タイムラインに推定を表示します。元の白黒写真は変更しません。保存時はメタデータをAtomicFileで更新します。写真は既存の長辺1600px以下の保存画像を1枚ずつ使います。

### 実機確認

1. 既存版を削除せず更新し、前の写真・メモが残ることを確認する。
2. 保存写真→サイズ推定→①脱毛範囲を斜めにドラッグして囲む。
3. 本数を空欄で保存し、範囲だけの記録が一覧・再表示・アプリ再起動後にも残ることを確認する。
4. ②比較範囲を黄色い枠と重ならない近くに置き、目視で確認できた毛の本数を入力する。
5. 推定値が表示され、保存後に一覧へ反映されることを確認する。
6. 範囲・本数の再編集と、編集中の画面回転、保存せず戻る動作を確認する。

撮影時のピントと見ずに撮る案内の改善事項は `docs/IMPROVEMENTS.md` に保持しています。

## 頭皮向けの自動撮影条件の調整（0.3.1）

中央の許容範囲を正規化距離0.10から0.18へ広げ、白い楕円で表示します。候補枠の中心が楕円内に入り、約1秒安定するとピント調整へ進みます。隣接フレームの中心移動は0.075、面積変化は60%まで許容し、髪の重なりによる小さな枠の変動で待機し直しにくくしました。画面に安定待ちの進捗とピント調整の状態を表示します。

頭皮では端末のAF成功通知を得られないことがあるため、AFを試みて最大1.4秒待ち、成功通知がなくても候補の位置・サイズ・映像の新しさを再確認して撮影します。ピントの成功を保証する方式ではなく、実機で保存写真の鮮明さを確認する必要があります。候補消失、ガイド外への移動、画面を離れた場合の撮影解除は維持します。

## ソナー音と自動撮影（0.3.0）

撮影画面で「ソナー音・自動撮影」をONにすると、候補が画面中央に近づくほど音が速くなります（メディア音量を使用）。中央付近で約1.6秒、候補の位置・面積が安定すると、その位置でオートフォーカスを行います。ピント成功と最新の候補位置を再確認して1枚撮影・保存し、一覧へ戻ります。手動撮影も使えます。

候補の消失、中央からの移動、位置・面積の急変、フレームの途切れで安定時間をリセットします。スイッチOFF、一覧への移動、アプリのバックグラウンド化で待機と音を解除します。古いフォーカス完了通知からは撮影しません。枠は検出候補なので、別の明るい領域を誤検出するとそこを撮る可能性があります。

### 自動撮影の実機確認

1. 既存版を削除せず更新し、以前の写真とメモが残ることを確認する。
2. メディア音量を上げ、撮影画面でソナー音・自動撮影をONにする。
3. 候補を中央へ寄せ、音が速くなることと、安定・ピント確認後の撮影・保存を確認する。
4. 安定待ち中に候補を外す、隠す、大きく動かすなどして撮影が止まることを確認する。
5. スイッチOFF、一覧へ戻る、ホーム画面へ移動する操作で音と自動撮影が止まることを確認する。
6. ピントが合わない場合に手動撮影できること、1回の自動撮影で写真が重複保存されないことを確認する。

## コントラスト検出の試作（0.2.0）

カメラ映像の明暗差から、暗い髪に囲まれた明るい領域を候補として黄色い枠で表示します。中央の十字と位置の案内を表示します。検出枠は保存写真に焼き込みません。撮影は引き続き手動です。

輝度（Y）成分だけを長辺160px以下へ間引き、毎秒最大5回処理します。明るさの分布に合わせたしきい値、連結領域、周囲の暗い領域の割合、縦横比で候補を絞ります。処理待ちフレームは蓄積せず、解析後は必ずフレームを解放します。プレビューとの座標変換はCameraXの共通Viewportと変換APIを使います。

この段階は検出位置を実写で確かめるための試作です。明るい髪、照明の反射、広い分け目、背景などで未検出・誤検出が起きます。黄色い枠は脱毛症の判定でも範囲の測定値でもありません。音・自動撮影はまだ追加していません。

### 追加の実機確認

1. 既存版を削除せずAPKで更新し、以前の写真とメモが残ることを確認する。
2. 髪と頭皮を同時に映し、黄色い枠が狙う場所に重なるかを縦・横向きで確認する。
3. 明るさや距離を変え、候補が見つかる条件・誤検出する条件を確認する。
4. 候補を中央へ移動したときの案内と、手動撮影・保存を確認する。
5. 数分間のプレビュー、画面回転、一覧への移動と復帰でフリーズしないことを確認する。

## 最初の版（0.1.0）

- 背面カメラの白黒プレビュー・手動撮影
- 写真を白黒JPEGに変換し、日時・任意のメモと端末内に保存
- 新しい順のタイムライン、写真の確認・削除
- カメラ権限を拒否しても一覧を利用可能

写真・メモはアプリ専用領域のみで管理します。ネットワーク権限なし、クラウド送信なし、OSバックアップ無効。アプリの削除・データ消去で記録は失われます。撮影写真をこのリポジトリに追加しないでください。

保存時は長辺1600px以下に縮小し、一覧には小さいサムネイルを読み込みます。画像処理とファイル操作は別スレッドで実施。今後の毛の解析に必要な解像度は、別途実写で検証します。

## 開発・インストール

Android Studioで開き、JDK 17以降・Android SDK 35を用意してGradle同期します。USBデバッグを有効にした実機を接続し、Runで起動します。

```sh
./gradlew assembleDebug testDebugUnitTest lintDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 実機での確認

1. 初回起動・権限の許可／拒否を試す。
2. 背面カメラのプレビューと保存画像が白黒になることを確認する。
3. メモ付きで縦向き・横向きそれぞれ撮影し、写真の向きを確認する。
4. アプリ再起動後に日時・写真・メモが残っていることを確認する。
5. 写真の削除で確認ダイアログが出ること、キャンセルと削除が機能することを確認する。
6. 連続撮影・画面回転・バックグラウンド復帰時の挙動を確認する。
